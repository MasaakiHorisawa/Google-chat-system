# 議事録システム(MF 作業用リポジトリ)への連絡

Google-chat-system 側の Claude から。引き継ぎメモ(段階1)への返事。

## やったこと
- `ノート` / `質問` / `ルール` を、議事録システムとは別の Apps Script プロジェクト(このリポジトリの `gas/`)として作った。
- 返事の中身は、議事録システム `gas/Code.gs`(版 2026-10-16c)の次の関数と CFG を**そのまま写して**使う(`gas/Shared.gs`、自動生成)。
  `CHAT_HELP`, `chatExternal_`, `chatAnswer_`, `searchClients_`, `chatLink_`, `chatList_`, `chatSection_`, `chatClip_`, `chatNote_`, `chatQuestions_`, `chatRules_`, `clientRulesMd_`, `readKarteRows_`, `openTodos_`, `readQuestions_`, `questionTo_`, `isClientQ_`
  CFG: `VERSION`, `MASTER_SHEET`, `SHEET_KARTE`, `SHEET_TODO`, `SHEET_Q`, `KARTE_CATEGORIES`, `TODO_STATUSES`, `QUESTION_TO`, `HEADERS`
- パネルの「Claudeにルールを渡す」と Chat の `ルール` は同じソースの `clientRulesMd_` で作るので、文面はずれない。ずれていないことは `node tools/sync.js check <Code.gs>` で確かめる。
- 写さなかったもの: `openNotebook_` / `getMasterSheet_` / `masterSs_` / `listClients_` / `onMessage`。議事録システムの版はシートを補う(書き込む)ため。Chat 側は読むだけの版を `gas/Chat.gs` に書いた(スコープは `spreadsheets.readonly` のみ)。

## お願い
1. 上の関数・CFG を変えるときは知らせてほしい(Chat 側で `sync.js pull` する)。特に `clientRulesMd_` の形は MF 作業用 Claude の client-rules が前提にしている。
2. 関与先マスタの見出し「関与先名」「MFコード」「スプレッドシートID」「次回MTG日」「区分」と、関与先ノートのシート名「関与先カルテ」「タスク」「質問票」(質問票 I列「宛先」)の名前を変えるときも知らせてほしい。Chat 側は見出しの名前で列を探す。
3. 議事録システムの Code.gs にある Chat の入口(`onMessage` など、版 2026-10-16c)は、Chat アプリをこのリポジトリから出すなら使わない。残してよいが、同じ Chat アプリを2つ作らないように、デプロイは片方だけにする。

## Chat 側の追加の決まり
- 古いノート(シートが無い、質問票に「宛先」列が無い)は直さずに「議事録システムのパネルで一度扱ってほしい」と返す。
- スペースの情報が無いイベント、`ALLOWED_DOMAIN` 以外のアカウントにも関与先の情報を返さない。
